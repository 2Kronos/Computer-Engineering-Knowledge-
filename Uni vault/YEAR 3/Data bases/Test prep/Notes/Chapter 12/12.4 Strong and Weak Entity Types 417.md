
### Strong vs. Weak Entity Types (Figure 12.12)

![image](https://github.com/user-attachments/assets/4cbd944d-d432-435b-a01c-5e31331133fd)


#### Key Concepts from the Diagram
1. **Strong Entity (Client)**
   - **Independent existence**: Can exist without other entities
   - **Primary key**: `clientNo` uniquely identifies each client
   - **Example attributes**: May include name, contact details, etc.

2. **Weak Entity (Preference)**
   - **Dependent existence**: Cannot exist without a Client
   - **No standalone primary key**: Depends on Client's `clientNo` for identification
   - **Partial key**: May have discriminator attributes (e.g., `prefType`)

#### Textbook Definitions
- **Strong Entity**: 
  - Not existence-dependent on another entity type
  - Has its own primary key (e.g., `clientNo` for Client)
  
- **Weak Entity**:
  - Existence depends on a strong "owner" entity
  - Requires the owner's primary key + partial key for identification
  

#### Database Implications
1. **SQL Implementation**:
```sql
-- Strong entity
CREATE TABLE Client (
    clientNo VARCHAR(10) PRIMARY KEY,
    name VARCHAR(50),
    email VARCHAR(100)
);

-- Weak entity
CREATE TABLE Preference (
    clientNo VARCHAR(10),
    prefType VARCHAR(20), -- e.g., "dietary", "accessibility"
    details TEXT,
    PRIMARY KEY (clientNo, prefType),
    FOREIGN KEY (clientNo) REFERENCES Client(clientNo)
);
```

2. **Real-World Analogy**:
   - **Client** = Person (can exist independently)
   - **Preference** = Food allergy (meaningless without knowing whose allergy it is)
