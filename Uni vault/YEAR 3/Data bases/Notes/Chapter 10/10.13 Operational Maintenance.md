
#### **🔹 What is Operational Maintenance?**  
The ongoing process of **monitoring, optimizing, and updating** a live database system to ensure performance, security, and adaptability to new requirements.  

---

### **📊 Key Maintenance Activities**  

#### **1. Performance Monitoring & Tuning**  
- **Tools**: DBMS utilities track:  
  - Query execution times.  
  - Lock conflicts/deadlocks.  
  - Storage efficiency.  
- **Actions**:  
  - Add/remove **indexes** to speed up queries.  
  - Adjust **storage structures** (e.g., partitioning tables).  
  - **Reorganize** tables if usage patterns change.  

#### **2. Upgrades & New Features**  
- Incorporate user feedback or business changes by revisiting earlier lifecycle stages (e.g., **requirements analysis** → **design**).  
- Example: Adding a "virtual tour" feature to *DreamHome*’s property listings.  

#### **3. Capacity Planning**  
- Forecast future resource needs (CPU, storage) based on:  
  - **Usage trends** (e.g., 20% annual data growth).  
  - **New applications** (e.g., mobile app integration).  

#### **4. Parallel Run & Transition**  
- **Safety Measure**: Run old and new systems simultaneously until consistency is verified.  
- **Checks**: Regularly compare outputs (e.g., report totals) to catch discrepancies.  
- **Fallback**: Maintain the old system if risks outweigh benefits (e.g., financial systems).  

---

### **⚡ Why This Matters**  
- **Prevents Degradation**: Continuous tuning avoids "slow creep" as data grows.  
- **Ensures Continuity**: Parallel runs minimize disruption during transitions.  
- **Future-Proofing**: Proactive upgrades keep the system aligned with business goals.  

**Example**:  
- A *DreamHome* DBA notices slow search queries → Adds an index on `property_type` → Performance improves by 40%.  

---

### **🔄 Iterative Process**  
Maintenance feeds back into the lifecycle:  
1. **New issues** → Trigger **redesign** or **reimplementation**.  
2. **User requests** → Lead to **new prototypes** or **features**.
