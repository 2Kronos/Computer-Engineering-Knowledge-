  

#### **🔹 What is Testing?**  
A systematic process to **identify errors** in the database system before deployment, using realistic data and planned strategies.  

---

### **🔍 Key Testing Goals**  
1. **Uncover Faults**:  
   - Detect bugs in **application logic** and **database structures** (e.g., missing constraints, incorrect queries).  
   - *Testing cannot prove absence of faults—only reveal their presence!*  
2. **Validate Performance**: Ensure the system meets speed, scalability, and usability requirements.  
3. **Assess Reliability**: Metrics from testing (e.g., error rates) measure software quality.  

---

### **🛠️ Testing Process**  
#### **1. Test Strategies**  
- **Realistic Data**: Use production-like datasets to simulate real-world usage.  
- **User Involvement**: End-users validate functionality (e.g., "Does the property search work as expected?").  
- **Separate Test Environment**: Ideal to avoid corrupting live data (backups are critical if real data is used).  

#### **2. Usability Evaluation** (Sommerville, 2010)  
| **Criterion**      | **Question to Ask**                                  |  
|--------------------|-----------------------------------------------------|  
| **Learnability**   | How quickly can a new user navigate the system?     |  
| **Performance**    | Does the system respond fast enough for workflows?  |  
| **Robustness**     | Can the system handle user mistakes gracefully?      |  
| **Recoverability** | How easily can errors be undone/rectified?          |  
| **Adaptability**   | Does the system support flexible workflows?         |  

**Example**:  
- A *DreamHome* agent should be able to **learn** the rental booking interface in <30 mins.  
- The system should **recover** automatically if a transaction fails mid-update.  
 

---

### **📜 "Sign-Off"**  
After successful testing:  
1. **Documentation**: Record test results and unresolved issues.  
2. **Handover**: Deploy the system to users (**Operational Maintenance**, Section 10.13).
